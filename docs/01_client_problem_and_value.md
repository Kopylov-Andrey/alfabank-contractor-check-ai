# Проверка контрагента: проблема клиента и ценность решения

**Статус:** финальная версия к защите  
**Дата:** 7 сентября 2026 года

## 1. Пользователь и задача

Основной пользователь — закупщик или менеджер юридического лица, которому перед договором, оплатой или выбором поставщика нужно быстро разобраться в данных о новом контрагенте.

По условиям кейса у пользователя уже есть банковский отчёт с регистрационными, финансовыми, судебными, реестровыми и риск-сведениями. Рабочая продуктовая гипотеза: основная потеря возникает не из-за отсутствия ещё одного скоринга, а из-за времени на поиск, сопоставление и перепроверку фактов в длинном отчёте.

## 3. Ценностное предложение

**«Контрагент — по фактам» превращает отчёт в короткую проверяемую сводку и диалог с AI.**

Пользователь получает:

- поиск компании по ИНН или названию;
- структурированную сводку по отчёту;
- точечные ответы на уточняющие вопросы;
- отдельную панель «Основание из отчёта» с полем, значением, датой и JSON-фрагментом;
- раздельное отображение общего риска и ЗСК;
- корректную обработку `0`, `null`, `[]` и отсутствующего поля;
- Web Search по конкретному запросу на актуальные внешние сведения;
- сравнение нескольких контрагентов по одинаковым фактическим показателям.

Продукт не создаёт собственный рейтинг и не принимает решение за пользователя. Его задача — сократить путь от отчёта к проверяемым фактам и следующему действию.

## 4. Пользовательский сценарий

1. Пользователь вводит ИНН или название компании.
2. Агент находит контрагента через MCP; неоднозначный выбор уточняется у пользователя.
3. Пользователь получает сводку по ключевым блокам отчёта.
4. При необходимости открывает «Основание из отчёта» и сверяет исходное значение.
5. Задаёт точечный вопрос в том же диалоге.
6. Для конкретного внешнего вопроса агент использует Web Search и явно отделяет открытые источники от банковского отчёта.
7. Для сравнения нескольких компаний агент формирует сопоставление по единым показателям без ранжирования по «надёжности».

## 5. Продуктовые гипотезы

AI-качество MVP проверяется отдельным regression-контуром. Продуктовые гипотезы ниже относятся к следующему этапу пользовательской валидации.

| ID | Гипотеза | Как проверять |
|---|---|---|
| P1 | Сводка сокращает время первичного анализа отчёта без потери точности | A/B-задача: исходный отчёт vs. отчёт + AI; время и точность |
| P2 | Диалог сокращает время поиска конкретного факта | Серия одинаковых точечных задач; медианное время ответа |
| P3 | Панель оснований ускоряет перепроверку ответа и повышает калиброванное доверие | Время проверки + интервью после выполнения задачи |
| P4 | Сравнение нескольких компаний сокращает ручное сопоставление | Сценарий выбора из 2–3 контрагентов; время и число ошибок |
| P5 | Web Search повышает полноту ответа на актуальные вопросы, которых нет в отчёте | Доля релевантных внешних вопросов с подтверждённым ответом |
| P6 | Полезная первая проверка повышает повторное использование сервиса для других контрагентов | 28-дневная повторная проверка другого ИНН |

## 6. Что уже подтверждено

Для текущего MVP подтверждено качество AI-поведения на фиксированном regression suite: фактическая корректность, полнота, работа с источниками, boundary-сценарии, Web Search, отсутствие критических ошибок и время ответа. Итоговый release gate пройден — подробнее в документе [03](03_hypotheses_evaluation_and_pilot.md).

Пользовательские и бизнес-метрики не подменяются AI-метриками: экономия времени, доверие и повторное использование остаются отдельными продуктовыми гипотезами для следующего этапа проверки.
