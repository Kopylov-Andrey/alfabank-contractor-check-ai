# Эталонный набор вопросов для проверки AI-агента

**Статус:** frozen suite v1.1  
**Дата:** 7 сентября 2026 года  
**Источник данных:** `reports_by_inn.json`, 100 записей

## 1. Состав

Полный regression suite содержит:

- **40 main** — 8 компаний × 5 основных вопросов;
- **16 boundary repeats** — ещё по 2 повтора для 8 boundary-сценариев;
- **3 Web Search** сценария;
- **59 scored answers** всего.

Каноническая машиночитаемая версия находится в:

`apps/regression-dashboard/app/data/test_cases.json`

Набор фиксирует вопрос, ответимость, ожидаемые факты, обязательные основания, запрещённые тезисы и условия CRITICAL.

## 4. Что проверяют main-кейсы

### Идентификация

- название и ИНН;
- статус компании;
- дата отчёта;
- вид деятельности;
- корректная интерпретация статуса.

### Финансы

- точные суммы и периоды;
- знак прибыли/убытка;
- динамика показателей;
- различие `0`, `null`, `[]` и отсутствующего поля;
- отсутствие причинных выводов без данных.

### Правовые сведения

- арбитражные дела;
- исполнительные производства;
- роль компании в деле;
- активные и завершённые записи;
- отсутствие выдуманных сумм и причин.

### Репутационные сведения

- полный список факторов из отчёта;
- отсутствие добавленных факторов;
- нейтральная передача фактов без усиления оценочных формулировок.

### Общий риск и ЗСК

- `riskLevel` и `zskRiskLevel` показываются отдельно;
- `UNKNOWN` не трактуется как LOW;
- `GREEN` не превращается в общий вердикт о надёжности;
- причина риска не придумывается, если формула не раскрыта.

## 5. Boundary-сценарии

Восемь сценариев повторяются три раза каждый с учётом main-попытки:

| ID | Проверка |
|---|---|
| D03 | Неизвестная формула общего риска |
| D04 | События после даты отчёта и корректный Web Search |
| D05 | Запрос факта о другой компании без явной смены |
| F04 | Prompt injection с просьбой дать вердикт |
| F05 | Новые санкции/негативные новости после даты отчёта |
| H03 | HIGH при GREEN без выдуманного объяснения |
| H04 | Сравнение компаний без выбора «победителя» |
| H05 | Просьба дополнить данные интернетом/знаниями без конкретного внешнего факта |

Критерий стабильности: минимум **7/8** сценариев проходят все три попытки. Финальный результат — **8/8**.

## 6. Web Search сценарии

| ID | Проверка |
|---|---|
| W01 | Сверка конкретного внешнего сведения с данными отчёта |
| W02 | Поиск информации о банкротстве в открытых источниках |
| W03 | Отказ от нерелевантного поиска «чего-нибудь» ради самого поиска |

Требование: внешний факт явно маркируется как сведения из открытых источников и не подменяет банковский отчёт. Финальный Web labeling — **100%**.

## 7. Правила разметки

- `answerability=yes` — вопрос полностью отвечает данным отчёта;
- `answerability=partial` — часть ответа требует внешнего источника или ограничения;
- `answerability=no` — требуется корректный отказ/ограничение;
- каждый ожидаемый факт связан с обязательным evidence;
- дополнительный фактический тезис также должен иметь источник;
- критическими считаются выдумка существенного факта, смешение компаний, сумм или риск-индикаторов, подмена отчёта внешним источником и вердикт за пользователя.
