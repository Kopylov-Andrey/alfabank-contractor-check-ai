# Гипотезы и проверка качества

**Статус:** финальная версия к защите  
**Дата:** 7 сентября 2026 года

## 1. Продуктовые и AI-гипотезы

Продуктовые гипотезы описывают пользовательский и бизнес-эффект и зафиксированы в документе [01](01_client_problem_and_value.md).

AI-гипотезы проверяют качество и устойчивость текущего MVP как интерфейса к данным отчёта.

## 2. AI-гипотезы и критерии

| ID | Гипотеза | Критерий |
|---|---|---|
| A1 | Агент корректно отвечает по фактам отчёта | Factual correctness ≥90% |
| A2 | Агент не теряет обязательные факты | Completeness ≥90% |
| A3 | Фактические утверждения сопровождаются источником | Source coverage ≥95% |

| A6 | Boundary-поведение устойчиво | ≥7 из 8 сценариев проходят все 3 попытки |
| A7 | Внешние сведения не смешиваются с отчётом | Web labeling 100% |
| A8 | Нет критических ошибок | CRITICAL = 0 |

## 3. Эталонный regression suite

Полный suite версии 1.1 включает:

- 40 основных кейсов;
- 16 повторов восьми boundary-сценариев;
- 3 Web Search сценария;
- **59 оцениваемых ответов**;
- 27 независимых диалогов;
- 86 вызовов агента вместе с setup-turns.

Boundary-сценарии: `D03`, `D04`, `D05`, `F04`, `F05`, `H03`, `H04`, `H05`. Они проверяют неизвестную формулу риска, внешние сведения, смену компании, prompt injection, Web Search и сравнение без ранжирования.

Машиночитаемый источник набора — `apps/regression-dashboard/app/data/test_cases.json`. Человекочитаемая спецификация — документ [04](04_ai_evaluation_test_cases.md).

## 4. Контур оценки

```text
Regression dashboard
  -> Yandex AI Studio agent
  -> LLM judge через KAILA
  -> deterministic validator
  -> PostgreSQL/SQLite
  -> manual review / override
```

LLM-судья возвращает `PASS / PARTIAL / FAIL / CRITICAL` и отдельные признаки factual correctness, completeness, source coverage, usefulness, false refusal и Web Search.

Deterministic validator независимо проверяет точные ИНН, названия, даты, суммы, уровни риска, обязательные факты и запрещённые утверждения. Ручная проверка используется для финального контроля спорных кейсов.

- все 40 основных кейсов имеют итоговый `PASS`;
- все 8 boundary-сценариев устойчиво проходят три попытки;
- Web Search корректно отделяется от данных банковского отчёта;

- полный regression suite завершён;
- p95 latency укладывается в выбранный ориентир.

Regression подтверждает качество AI-поведения на зафиксированном наборе и готовность текущей версии агента к демонстрации MVP.

## 8. Следующий этап продуктовой проверки

AI-качество и продуктовый эффект оцениваются отдельно. После технической валидации MVP следующий шаг — проверка продуктовых гипотез из документа 01: экономии времени, удобства перепроверки, качества сравнения и повторного использования.
