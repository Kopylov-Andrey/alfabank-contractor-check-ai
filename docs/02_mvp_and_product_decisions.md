# MVP и продуктовые решения

**Статус:** финальная версия к защите  
**Дата:** 7 сентября 2026 года

## 1. MVP «Контрагент — по фактам»

MVP — публичный веб-интерфейс к AI-агенту Yandex AI Studio, который работает с банковскими отчётами через MCP и использует Web Search как отдельный внешний источник для конкретных актуальных вопросов.

Реализованный пользовательский контур:

- поиск компании по ИНН или названию;
- получение отчёта через MCP;
- структурированная сводка;
- уточняющий чат;
- панель «Основание из отчёта»;
- раздельное отображение общего риска и ЗСК;
- корректная обработка `0`, `null`, `[]` и отсутствующего поля;
- Web Search по конкретному внешнему вопросу;
- сравнение 2–10 компаний по фактам;
- публичный demo;
- отдельный regression/evaluation dashboard.

## 2. Основной пользовательский сценарий

**Поиск/ИНН → выбор компании → сводка → основание → уточняющий вопрос → при необходимости внешний поиск или сравнение.**

Правила выбора компании:

- точный ИНН используется для прямого получения отчёта;
- название разрешается через `search-contractors`;
- неоднозначный результат уточняется у пользователя;
- активная компания сохраняется до явной смены или сравнения;
- отдельный вопрос о другой компании не приводит к скрытому переключению;
- сравнение запускается только по явному запросу пользователя.

## 3. Границы продукта

| В MVP | За пределами MVP |
|---|---|
| Сводка и чат по отчёту | Собственный риск-скоринг поверх банковского отчёта |
| Основания из отчёта | Автоматическое ранжирование компаний по «надёжности» |
| Web Search по конкретному внешнему вопросу | Подмена банковского отчёта внешними данными |
| Сравнение нескольких компаний | Юридическая, финансовая или комплаенс-консультация |
| Работа с пробелами данных | Принятие решения за пользователя |
| Публичный demo | Интеграция с внутренними банковскими системами |

## 4. Evidence: «Основание из отчёта»

Панель основания делает ответ проверяемым без необходимости искать нужное место в исходном JSON. Для факта пользователь видит:

- название факта;
- поле отчёта;
- точное значение;
- дату отчёта;
- исходный JSON-фрагмент.

Demo API передаёт в браузер только необходимый whitelist полей для evidence panel; служебные данные инструмента остаются на серверной стороне.

## 5. Работа с Web Search

Web Search используется как вторичный источник, когда пользователь просит проверить **конкретное внешнее сведение**: новости, санкции, сайт/адрес или события после даты отчёта.

Продуктовые правила:

- ИНН определяется только через MCP;
- каждый внешний факт явно маркируется как сведения из открытых источников;
- для событий после даты отчёта показывается `reportDate` как граница банковских данных;
- при расхождении пользователю показываются оба источника;
- нерелевантный поиск ради самого факта использования интернета не выполняется.

## 6. Сравнение компаний

Для явного сравнения агент использует `compare-contractors` для 2–10 ИНН.

Сравнение:

- использует одинаковые фактические показатели;
- показывает источник каждой строки;
- сохраняет раздельность данных компаний;
- не превращает сравнение в собственный рейтинг.

## 7. Ключевые продуктовые решения

| Решение | Пользовательская причина | Проверка |
|---|---|---|
| Отчёт — основной источник | Понятно происхождение факта | Source coverage + ручная сверка |
| Web Search отделён от отчёта | Не смешиваются даты и происхождение данных | Web scenarios + labeling |
| Общий риск и ЗСК раздельно | Это разные индикаторы | D02/E05/F03/H01/H02 |
| `0`, `null`, `[]`, missing различаются | Пустота не превращается в ложный вывод | A03/C02/F01 |
| Активная компания меняется только явно | Снижается риск смешения данных | D05 + повторы |
| Сравнение без ранжирования | Пользователь получает факты, а не скрытый скоринг | H04 + comparison checks |
| Основания вынесены в UI | Ответ можно быстро перепроверить | Evidence panel + source coverage |

## 8. Критерий готовности MVP

Готовность оценивается отдельно от будущих продуктовых метрик. Для AI-части используется frozen regression suite из 59 scored cases с release gate по factual correctness, completeness, source coverage, usefulness, boundary stability, Web labeling и отсутствию CRITICAL.

Финальный release gate пройден. Подробные критерии и результат — в документе [03](03_hypotheses_evaluation_and_pilot.md).
